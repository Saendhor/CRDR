# BPP Discrepancy Analysis: CRDR (0.08 bpp) vs DDS (~10 bpp)

## Summary
The 125× difference between CRDR's average bpp (0.08) and DDS's average bpp (~10) is **not a bug** — it reflects fundamentally different compression approaches operating in different domains.

## What CRDR Measures (0.08 bpp)
- **File**: `_avg_bitrate.json` generated by `scripts/compress.py`
- **What's compressed**: Entropy-coded latent codes from a learned model
- **`.bin` file contents**: 
  - 5-byte header (4 bytes image size + 1 byte max value)
  - Entropy-coded `z_str` (hyperprior latent)
  - Entropy-coded `y_str` (main latent)
- **Formula** (line 109 of `scripts/compress.py`):
  ```python
  real_bpp = actual_byte * 8 / H / W
  ```
  where `actual_byte = os.path.getsize(bin_path)` (the `.bin` file size on disk)
- **Why so low**: The model uses learned probability distributions and arithmetic coding, achieving near-Shannon-limit compression of the latent representations. The latens contain "information content" rather than raw pixel data.

## What DDS Measures (~10 bpp)
- **Script**: `eval_bpp.sh` from `/home/commando/Projects/CINECA/script_for_dataset/`
- **Formula** (same formula, different data):
  ```text
  bpp = (Compressed File Size in Bytes × 8) / (Image Width × Image Height)
  ```
- **What's compressed**: Raw pixel data using block-compressed texture formats
- **Default format**: DXT5 (via ImageMagick `convert_png_to_dds.sh`)
- **DXT5 structure**: 16 bytes per 4×4 pixel block
- **Typical calculation** for 768×512 image:
  - Blocks: ceil(768/4) × ceil(512/4) = 192 × 128 = 24,576
  - Bytes: 24,576 × 16 = 393,216
  - bpp = 393,216 × 8 / (768 × 512) ≈ 8.0 bpp
- **Why higher**: Fixed block codebooks, no entropy coding advantage. The bpp is determined by the format's design, not by "information content."

## The Fundamental Difference

| Aspect | CRDR | DDS (Block Compression) |
|---|---|---|
| **What's compressed** | Latent codes (learned probability models) | Raw pixel data (fixed block codes) |
| **Coding method** | Arithmetic entropy coding | Block-based fixed codebooks |
| **Achievability** | Near Shannon limit | Fixed by format design |
| **Typical bpp** | 0.01–0.1 bpp | 4–16 bpp (depends on format) |
| **Compression goal** | Encode "what the image is" efficiently | Encode pixel values efficiently in spatial domain |

## No Bug in Either Script
Both scripts compute valid bpp values for their respective formats. The discrepancy simply reflects:
- CRDR compresses **learned latent representations** with entropy coding
- DDS compresses **raw pixel data** with fixed block codes
- They operate in different domains and compress different things

## Example: 768×512 Image
- **CRDR**: `.bin` file might be ~3,000 bytes → bpp ≈ 0.08
- **DDS (DXT5)**: 393,216 bytes → bpp ≈ 8.0 (or ~10 depending on dimensions/alignment)
- **Ratio**: ~100× — CRDR is compressing the "essence" of the image, DDS is compressing the pixel grid itself

## Proper Comparison: CRDR vs DDS bpp
In `bpp_export.txt`: `0.08` vs `~10` are both `bytes*8/H/W`, but different things — no direct comparison is valid.

- `scripts/compress.py:109`: `.bin` payload = entropy-coded latents (`src/utils/codec_utils.py:128-133` + 5-6B header). Content-adaptive, `0.01-0.1 bpp`.
- `eval_bpp.sh`: `.dds` payload = fixed `4x4` blocks (`DXT1=8B/block=4bpp`, `DXT5=16B/block=8bpp` + 128B header + padding). Content-independent.

Proper comparison = same images, same denominator, rate-distortion — not rate alone:

1. Same source set: start from same `*.png`. `H*W` must be original PNG (`identify`), not padded dims.
2. Fix `eval_bpp.sh`: it matches `original/$name.png` to `compressed/$name.png` and skips otherwise. For DDS either rename to stem-match or compute as:
   ```bash
   comp_bytes=$(stat -c%s img.dds); dims=$(identify -format "%w %h" orig.png)
   bpp=$(awk "{print ($comp_bytes*8)/($W*$H)}")
   ```
   Decide header handling and document it: include full file (like CRDR `actual_byte`) or subtract 128B DDS header. Disable mipmaps in `convert_png_to_dds.sh`, fix `DXT1/DXT3/DXT5/BC7/none` — each is a single point.
3. Add distortion axis:
   - CRDR: `compress.py --decompress` -> `recon.png` + `_avg_bitrate.json`
   - DDS: `convert_png_to_dds.sh` -> `.dds` -> `convert_dds_to_png.sh` (`magick`, not `ffmpeg`) -> `recon_dds.png`
   - `scripts/calc_metrics.py:329-353`: run on both `fake_dir` vs same `real_dir` for `PSNR/LPIPS/DISTS/FID` at that `bpp`.
4. Report as `bpp_dds/bpp_crdr @ equal quality`, or plot RD curve: sweep CRDR `-q 0.0-4.0`, DDS gives 1 point per format. `ratio=orig_bpp/comp_bpp` alone only proves storage saving, not quality — DDS preserves random-access/GPU use, CRDR does not.

## Lowering DDS bpp to Approach CRDR (0.08 bpp)

You cannot reach 0.08 bpp with DDS alone — the format floor is 4 bpp (~50x above CRDR).

| Format | Bytes / 4x4 block | Theoretical bpp |
|---|---|---|
| DXT1/BC1 | 8B | 4.0 |
| DXT3/BC2, DXT5/BC3 | 16B | 8.0 |
| none | raw | 24-32 |

Observed ~10 bpp is DXT5 (8.0) + 128B header + padding/mipmaps. `QUALITY` in `convert_png_to_dds.sh` does not change DDS size (fixed-rate).

What to do, in order:

1. Switch DXT5 -> DXT1 (2x saving, 8 -> 4 bpp):
   ```bash
   ./convert_png_to_dds.sh /path/to/pngs ./dds_dxt1 DXT1
   ```
   Only if you do not need alpha — DXT1 has no alpha.

2. Disable mipmaps (~1.33x saving):
   `convert_png_to_dds.sh` now takes a 5th arg `mipmaps` (default 0) and passes `-define "dds:mipmaps=$MIPMAPS"` to magick:
   ```bash
   ./convert_png_to_dds.sh /path/to/pngs ./dds_dxt1 DXT1 100 0
   ```
   If previous `.dds` files contained mipmaps, this alone drops ~10 -> ~8 for DXT5, ~4 for DXT1.

3. Measure correctly:
   `eval_bpp.sh` looks for `compressed/$filename` with the same `.png` name, so it skips `.dds`. Use:
   ```bash
   comp_bytes=$(stat -c%s img.dds); read W H <<<$(identify -format "%w %h" orig.png)
   echo "$comp_bytes $W $H" | awk '{printf "%.4f\n", ($1*8)/($2*$3)}'
   ```
   Denominator must be original H*W.

4. If you must go below 4 bpp with DDS: downscale before encode, e.g. `-resize 50%` gives ~1 bpp effective (4 * 0.25), `-resize 25%` gives ~0.25 bpp. Quality loss is severe and defeats the purpose — only useful for RD-curve.

Real fix: change codec. For 0.08-range with GPU usability use Basis Universal ETC1S / KTX2+Zstd (~0.5-1.5 bpp), or BC7 + supercompression, not legacy DDS. If GPU random-access is not required, just use CRDR .bin.

Mipmaps are precomputed downscaled copies of a texture stored inside the same .dds file.
- Level 0: original WxH
- Level 1: W/2 x H/2, Level 2: W/4 x H/4, ... down to 1x1
- Total overhead: 1 + 1/4 + 1/16 + ... ~= 1.33x file size. That's why convert_png_to_dds.sh:16 defaults to mipmaps=0 for lowest bpp.
- Purpose: GPU sampling. When a surface is far/small on screen, GPU samples a small level instead of the full texture. Avoids aliasing/shimmer and improves cache performance. Required for trilinear filtering.
- Tradeoff: keep 1 for in-engine use, 0 for bpp comparison or single-level inference.
